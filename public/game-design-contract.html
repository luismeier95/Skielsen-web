CONTRACT V1.0

01

HIERARCHIE

Theme Contract = Farben und Kontraste. Game Design Contract = Layout und Komponenten. Game Module = Mechanik.

02

CANVAS

Alle Games verwenden denselben Canvas: Desktop max. 760 px, Mobile 100 %. Keine eigene App-Breite pro Game.

03

HEADER

72 px Desktop, 52 px Mobile. Links Logo + Game Name, rechts Meta + Minimieren. Kein Game baut einen eigenen Header.

04

PROGRESS

Direkt unter dem Header, 4 px hoch. Zeigt Game Progress, nicht verbleibende Zeit.

05

STATUS BANNER

Maximal drei Werte. Im Result-State verschwinden alle Werte und der Banner zeigt ausschließlich ERGEBNIS.

06

TYPOGRAFIE

Display für Hauptbegriffe, Zahlen und Resultate. UI für Labels, Namen, Buttons, Tabellen und Copy.

07

TYPE SCALE

Micro 6–7 px, UI 8–10 px, Copy 12 px, Werte 18–26 px, Hauptobjekte 34–58 px, Result 40–68 px.

08

SURFACES

Cards nutzen nur Theme Surface, On-Surface, Border und Shadow. Standardmäßig keine Border-Radii.

09

PLAYER IDENTITY

Rot, Blau, Grün und Gelb bleiben semantische Identitätsfarben. Sie dürfen das Theme nicht ersetzen.

10

BUTTONS

Nur Primary, Secondary, Gameplay Choice und Danger. Keine Game-eigenen Buttonfarben oder zufällige Varianten.

11

FEEDBACK

Nur Success, Warning und Error. Farben kommen immer aus Theme-Tokens.

12

SCOREBOARD

Player Rows folgen einem gemeinsamen Pattern: Farbmarker, Name, Game-Wert. Keine separate Darstellung je Game.

13

RESULT PAGE

Jedes Game endet gleich: ERGEBNIS → Result Table → TURNIER ANSEHEN.

14

RESULT TABLE

Ein gemeinsames Tabellen-Component. Nur Spalten und Werte sind Game-spezifisch.

15

GAME STATES

Jedes Game mappt auf SETUP, READY, PLAY, REVEAL, RESULT.

16

GAME-SPEZIFISCH

Nur der zentrale Mechanik-Bereich darf einzigartig sein, z. B. 7-Segment-Timer, Wortfelder oder Kategorie-Vergleich.

17

ANIMATION

Standard 180–280 ms. Keine eigene Animationssprache je Game. Ausnahmen nur für spielrelevante Mechaniken.

18

RESPONSIVE

Primärer Breakpoint 720 px. Weitere Breakpoints nur bei zwingender Mechanik-Notwendigkeit.

19

CSS ARCHITEKTUR

Gemeinsame Klassen tragen Präfix skg-. Game-CSS enthält nur Mechanik-spezifische Komponenten.

20

NON-NEGOTIABLE

Kein eigener Header, keine eigenen globalen Farben, keine eigene Content-Breite, kein eigener Result-Screen, keine Hardcoded Theme-Farben.

ARCHITEKTUR

THEME → CONTRACT → GAME
